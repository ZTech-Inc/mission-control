### New Components

#### 1. `SkillChip` (replaces `ProfileChip` for skills field only)

**Location:** `agent-detail-tabs.tsx` (local to file, not exported)

**Variants:**
- **Plain** (no catalog match): Renders identically to existing `ProfileChip` -- a non-interactive `<span>` with class `inline-flex items-center rounded-full border border-primary/20 bg-primary/10 px-2.5 py-0.5 text-xs font-medium text-primary`.
- **Linked** (catalog match found): Renders as a `<button>` with enhanced hover states. Class: `inline-flex items-center rounded-full border border-primary/30 bg-primary/10 px-2.5 py-0.5 text-xs font-medium text-primary underline-offset-2 hover:bg-primary/20 hover:underline transition-colors cursor-pointer`.

**Props:**
```typescript
{
  label: string           // Display text from agent's skills array
  catalogEntry?: {        // Populated when normalized name matches skillsList
    source: string
    name: string
  } | null
  onOpen?: (source: string, name: string) => void  // Opens inline detail
}
```

**Interaction contract:**
- Click on linked chip opens inline skill detail view (see below)
- Focus ring: `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`
- No tooltip on plain chips
- Linked chips show pointer cursor

#### 2. `InlineSkillDetail` (inline detail view within agent drawer)

**Location:** `agent-detail-tabs.tsx` (local to file)

**Purpose:** Displays SKILL.md content inline within the agent detail panel when a linked skill chip is clicked. Avoids navigation away from current agent context.

**Layout:**
- Rendered below the `ProfileTab` content (or as an expanding section within Capabilities)
- Background: `bg-muted/50 rounded-lg border border-border`
- Padding: `p-4` (16px)
- Max height: `max-h-64` with `overflow-y-auto`

**States:**
- **Loading:** Skeleton line shimmer, 3 lines of `h-3 bg-muted rounded animate-pulse`
- **Loaded:** Skill name as heading (`text-sm font-semibold`), source badge (`text-2xs text-muted-foreground`), description/content as body (`text-sm text-foreground whitespace-pre-wrap`)
- **Error:** Error message in `text-sm text-destructive` with "Try again" text button
- **Closed:** Not rendered (null)

**Header row:** Flex row with skill name left-aligned, close button right-aligned.
- Close button: `text-xs text-muted-foreground hover:text-foreground` with text "x" (no icon library)

**Data fetching:** Uses existing `GET /api/skills?mode=content&source=<s>&name=<n>` endpoint. Must handle `org-agent:*` sources (requires API fallback -- see RESEARCH.md Pitfall 5).

## Interaction Contracts

### Skill Chip Linking Logic

1. `ProfileTab` reads `skillsList` from `useMissionControl()` store
2. For each skill in `agent.skills`, normalize: `skill.toLowerCase().replace(/[\s_]+/g, '-')`
3. Compare normalized skill name against normalized `skillsList[].name`
4. If match found, render `SkillChip` with `catalogEntry` populated
5. If no match or `skillsList` is null (not loaded), render plain `SkillChip` (no link, no fetch)

### Inline Detail Open/Close

1. User clicks linked `SkillChip`
2. `ProfileTab` sets `openSkill` state to `{ source, name }`
3. `InlineSkillDetail` renders below Capabilities section
4. Fetch fires via `useEffect` on `openSkill` change
5. User clicks close button or clicks a different skill chip (replaces current)
6. Pressing Escape while detail is open closes it

### Keyboard Accessibility

- All linked chips are `<button>` elements (natively focusable, Enter/Space activates)
- Tab order follows DOM order (chips appear left-to-right, top-to-bottom in flex-wrap)
- Inline detail close button is focusable
- Escape key closes inline detail view

## Phase-Specific Notes

### Scope Boundaries

- This phase adds NO new pages or routes to the UI
- All UI changes are contained within `agent-detail-tabs.tsx`
- The skills catalog panel (`skills-panel.tsx`) is NOT modified -- it already handles `org-agent:*` entries via its existing rendering logic once they appear in the store
- The `SOURCE_LABELS` map in `skills-panel.tsx` should be extended with an `org-agent:*` pattern handler to display agent skill sources properly

### What Changes Visually

1. **ProfileTab > Capabilities > Skills field:** Chips that match catalog entries gain hover underline and pointer cursor. Chips that do not match remain visually identical to current state.
2. **ProfileTab > Below Capabilities (conditional):** An inline detail panel appears when a linked chip is clicked, showing the SKILL.md content in a bordered, muted-background container.
3. **SkillsPanel sidebar groups:** After org scan, a new source group `org-agent:<name>` appears in the skills catalog sidebar. This requires NO code change to the panel itself -- the grouping logic already handles arbitrary source keys.

### What Does NOT Change

- No changes to spacing scale, color tokens, or typography scale
- No changes to agent cards, task board, or any panel outside agent detail
- No new CSS custom properties needed
- No new Tailwind config entries needed
